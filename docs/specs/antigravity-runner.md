# Google Antigravity CLI pipeline integration

- **Status:** proposed; Hugo requested this maintenance change on 2026-10-20 to bring Google's agent and models into the multi-agent pipeline.
- **Requirements:** `OPS-08`, `SEC-01`, `SEC-04`, `SEC-07`.
- **Scope:** add Google's Antigravity CLI (`agy`) as a selectable builder and reviewer. This does not start a new site stage.

## Why the CLI

Antigravity's IDE is interactive and runs on Hugo's machine, so it cannot run in the pipeline. Its CLI can: it has a non-interactive print mode (`-p`) and reads a Gemini API key. Google's own Gemini CLI repository says that Gemini CLI "was replaced by Antigravity CLI on June 18th, 2026" for unpaid and Google One users, and it is not optimized for Gemini 4 Argon, so the integration uses `agy`. Jules, Google's cloud agent, opens its own PRs outside the pipeline's checks and is not used, for the same reason as Copilot's cloud agent.

## Contract

1. `AGY-01`: the `agent-runner` image fetches Antigravity CLI 1.4.3 from the exact build URL in Google's public bucket, checks the sha512 that Google's manifest published for it, installs it root-owned and read-only as `agy`, checks the version while building, and bakes a root-owned launcher, `scripts/antigravity-runner.ts`. Google's install script is not used: it always follows the latest manifest. Register `antigravity` with `git`, `node`, `browser` and `web`, the model family `google`, no Figma, and `status: pending`.
2. `AGY-02`: run in print mode with an explicit model slug from the registry (`auto` refused). The registry model is `gemini-4-argon-medium`, with `gemini-3.8-flash-high` as plan B (both chosen by Hugo on 2026-10-20 from the slugs `agy models` listed for his key; the suffix is the reasoning level). Plan B is a reviewed registry edit followed by a new smoke, never a silent fallback. With no model, a run of this agent stops in `prepare`, before any key is read. Only the agent step receives `AGENT_KEY_ANTIGRAVITY`, as `GEMINI_API_KEY`; the launcher writes `settings.json` with `modelProvider: "gemini"` in a throwaway home, so the CLI uses the key and never starts a browser sign-in.
3. `AGY-03`: retain the existing unprivileged Docker boundary, read-only `.git`, separate publisher, secret scanning and Hugo's approval. Build mode uses `--mode accept-edits` and approves only `npm`, `npx`, `node`, read-only `git`, `ls` and `mkdir` through `permissions.allow`; other actions are denied in print mode. Never `--dangerously-skip-permissions` or `--mode auto`. Slash commands are disabled in build mode (in review mode that flag would turn off plan mode). The launcher starts the root-owned binary by absolute path. No ADC, service account or custom endpoint variable reaches the CLI. The CLI's permissions are additional controls, not an operating-system sandbox.
4. `AGY-04`: a separate manual smoke workflow (`antigravity-smoke.yml`) runs the fixed OpenCode fixture without opening a PR, modifying the repository or starting a site stage, only for Hugo on `main`, and verifies the files outside the container. The PR sandbox smoke checks, without any credential, that the binary and the launcher are in the image and read-only to the agent.
5. `AGY-05`: suppress the transcript. Fail on a nonzero exit, a structured `AGY_ERROR` line (only its status and code are shown), an `Error:` line (redacted), or an interactive sign-in request, which also stops the CLI at once.
6. `AGY-06`: as a reviewer (`agent-review.yml`), run in `--mode plan` with only read-only `git` approved; the launcher, not the agent, writes the printed answer to `.agent/review.md`, redacted and size-limited. A PR that touches `.gemini/`, `.agents/` or `GEMINI.md` is treated like other agent configuration by the reviewer checks.
7. `AGY-07`: document the owner setup in `docs/agents/antigravity.md`: key, spend cap, secret, label, model choice, image publication and smoke.
8. `AGY-08` (added 2026-10-20): `figma-read` stages and web reads. The launcher writes `~/.gemini/config/mcp_config.json` (the format of `agy mcp add`) pointing through the pipeline's Figma gateway (`http://figma-gateway:8787/mcp`), which holds the token and enforces the stage's tools on the design file, with only the read tools of `agent-run.yml` (`get_metadata`, `get_screenshot`, `get_variable_defs`, `get_design_context`) approved as `mcp(figma/<tool>)` rules. Reviews never get Figma, and `figma-write` stays with Codex and Claude Code. To verify on the agent's first `figma-read` stage. Build mode also approves `read_url(<domain>)` for the npm registry and the NASA domains of `docs/SETUP.md`, so the `web` capability is not denied in print mode; the rule forms `mcp(<server>/<tool>)` and `read_url(<domain>)` come from the guidance bundled in the 1.4.3 binary.

## Allowed protected changes

The proposed `agent-run.yml`, `agent-review.yml`, `agent-runner-image.yml` and `agent-sandbox-smoke.yml` under `docs/agents/workflows/`, a new proposed `antigravity-smoke.yml` there, and `docs/agents/README.md`, `other-agents.md`, `adding-an-agent.md` and a new `docs/agents/antigravity.md`. Hugo copies the workflow proposals to `.github/workflows/`. No repository setting, environment, secret or variable is changed by an agent.

## Verification

- Checked on 2026-10-20 with the pinned binary, downloaded from the manifest's URL, sha512 verified, run in an isolated home with no credential: `agy --version` prints `1.4.3`; `--help` lists `--print`, `--model`, `--mode`, `--output-format`, `--disable-slash-commands`, `--log-file`, `--print-timeout`, `--sandbox` and `--dangerously-skip-permissions`; without a key, print mode waits for a browser sign-in. The changelog bundled in the binary documents the Gemini API key setup (`modelProvider: "gemini"` and `GEMINI_API_KEY`), `--mode` being honoured in print mode, `settings.json` permissions (`permissions.allow`, `command(...)`; the 1.1.0 changelog prose spells the key `permission.allow`, whereas the 1.4.3 settings schema and `cli_setting_manager.go` log use `permissions.allow`) being honoured in print mode, denials not failing a print run, `--model` failing instead of falling back, and `AGY_ERROR` lines with exit code 3.
- Unit and process tests cover the model rule, the argument list and settings, environment isolation, key-only authentication, suppressed output, failure detection and the review file.
- Workflow tests cover the pinned download and hash, trusted actor and `main` guards, one-step key exposure, container mounts, the reviewer branch and the absence of publication credentials in the smoke.
- Checked on 2026-10-20 with the real 1.4.3 binary and the real launcher, using a dummy key (not a credential): with the launcher's settings the CLI calls the Gemini API directly and fails in 1 to 2 seconds with `AGY_ERROR` (`INVALID_ARGUMENT`, 400, `API_KEY_INVALID`) and exit code 3, in both build and review mode; it never starts a browser sign-in, the key does not appear in the launcher's message, and the throwaway home is removed. The PR sandbox smoke repeats this check on every change.
- **To verify on the first real run:** that `command(npm)` approves `npm` with any arguments; that build mode completes the fixture and its test; duration and cost. If the allow list is not honoured, the smoke fails; the fix is a reviewed change, never `--dangerously-skip-permissions`.

## Risks and how they are handled

- **A build published the same day.** 1.4.3 was published on 2026-10-20 (the bucket's `last-modified`). No older build can be pinned: the bucket cannot be listed, and the update service's manifest ignores version or channel parameters and always returns the latest build (checked with `?version=1.4.2`, `?channel=stable` and versioned paths). Handling: the build is pinned by URL and sha512, so it cannot change silently; the runner image is pinned by digest, so the binary Hugo's smoke qualified is the one every later run uses; the agent stays `pending` until that smoke passes. A later build is adopted only through a reviewed PR that changes the three `AGY_*` arguments.
- **The background updater.** In 1.4.3 every run starts an updater that contacts Google's update service, and no setting or variable turns it off (five candidate settings were tried). Handling: in the image the version check runs with `RUN --network=none` and the binary hash is checked again afterwards, so the updater cannot swap the binary while the image is built; at run time the launcher starts the root-owned `/opt/agy/antigravity` by absolute path, which the agent's user cannot write, so a build the updater might leave in the agent's throwaway home or on its `PATH` is never launched.
- **A browser sign-in that waits.** Without the Gemini API settings, print mode prints a sign-in URL and waits for a code. Handling: the launcher always writes `modelProvider: "gemini"`, refuses to start without the key, and kills the CLI as soon as a sign-in request appears.
- **Plan mode disabled by another flag.** In 1.4.3, `--disable-slash-commands` makes `--mode plan` ineffective. Handling: review mode does not pass it; build mode, whose `accept-edits` mode is unaffected, does.
- **Spending.** A Gemini API key's spending is bounded by the Google Cloud project's spend cap or prepaid credits, which Hugo sets; the bundled changelog says key sessions stop when that cap is reached.

## Out of scope

Antigravity's IDE and remote control, Jules, Vertex AI or service-account authentication, Figma write access, and changes to approval or deployment policy.
